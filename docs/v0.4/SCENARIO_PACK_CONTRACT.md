# Observer v0.4 Scenario Pack contract and loading boundary

Created at: 2026-08-25 20:00 Beijing time (UTC+8)
Last updated at: 2026-08-26 22:40 Beijing time (UTC+8)

Status: repository implementation complete for the v0.4 synthetic gate; external target-user pilot evidence remains required.

## Version boundary

This work adds `fs-observer/scenario-pack-manifest/1` beside the frozen `fs-observer/foundation-case-pack-manifest/1` contract. It does not modify the Foundation CASE005 Schema, intake, adapter, snapshot, or IG2/IG6 gates.

The v0.4 contract contains the exact fields required by the v0.4 architecture baseline:

`pack_id`, `version`, `digest`, Observer and Engine compatibility lists, input Schema reference, subject types, knowledge requirements, Profile references, expected observation, reason-code namespace, evidence requirements, human-review template, golden cases, value metrics, and known limitations.

Unknown fields fail validation. A future field therefore requires an explicit contract revision; it cannot be silently ignored.

## Loading algorithm

1. Resolve the Pack root and reject a missing directory or reparse-point root.
2. Load `scenario-pack.manifest.json` and validate it against the v1 JSON Schema.
3. Require an exact, case-sensitive entry for the running Observer and Engine versions. Ranges and guessed compatibility are not accepted in v1.
4. Reject duplicate identity lists and duplicate golden-case or metric identifiers.
5. Resolve input Schema, Profile, review-template, and golden-input references below the Pack root. Absolute paths, backslashes, empty segments, `.`/`..`, missing files, and reparse points fail closed.
6. Parse the declared input Schema as JSON Schema.
7. Recompute the whole-Pack digest and compare it using exact lowercase SHA-256 text.
8. Verify detached `scenario-pack.signature.json` against an explicitly supplied trust store. Missing signatures, unknown keys, identity substitution, malformed metadata and invalid RSA-SHA256 signatures fail closed.
9. Freeze the successfully loaded identity as `pack_id@version@digest`. Reinstalling the same identity is idempotent; a different digest under the same `pack_id@version` is rejected.

## Digest contract

`fs-observer/scenario-pack-digest/1` is SHA-256 over `FS-OBS-CANON-1` canonical JSON with this logical shape:

```json
{
  "digest_contract": "fs-observer/scenario-pack-digest/1",
  "manifest_without_digest": {},
  "payload_files": [
    { "path": "ordinal/relative/path", "sha256": "lowercase-sha256" }
  ]
}
```

All regular files below the Pack root except `scenario-pack.manifest.json` and detached `scenario-pack.signature.json` are included, ordered by ordinal normalized relative path. Adding, removing, renaming, or changing any payload file changes the digest. The signature file is excluded only to avoid a digest/signature cycle; it signs the resulting identity and is independently verified.

## Evidence provided by this slice

- One strict Schema and typed DTO set.
- One fail-closed loader, an in-memory registry for isolated use, and immutable SQLite Pack/task bindings with restart recovery.
- Two different synthetic Pack structures accepted by the same code path.
- Negative tests for payload tampering, missing/invalid/stale signatures, Observer mismatch, Engine mismatch, path escape, unknown fields, and identity substitution.

## Implemented execution and pilot boundary
- Batch import is idempotent, restartable and bound to frozen Pack identity.
- The local CLI command `observer scenario-pack-run` is the v0.4 minimum controlled entry. It runs
  one declared Golden Case through the real Engine v1.5 path and persists candidate-only output;
  it is not a remote service, enterprise controller or target-user pilot completion.
- Pack Profile `ref/id/version/digest` values are explicit replay anchors; they do not replace the Engine v1.5 Profile identity.
- Batch input runs through the real Engine v1.5 path and is projected only as a candidate result. A hard gate is rejected.
- Human-review records, five-metric ledger entries, exports and v0.4 audit events are append-only.
- Golden, boundary and adversarial fixtures remain synthetic and prove no enterprise effectiveness.
- Pilot package templates are intentionally marked `DRAFT_NOT_*`; real authorization, review, acceptance and deletion evidence cannot be generated by repository tests.

## Explicit exclusions

- Production trust-root provisioning and key-rotation policy; the repository key is explicitly limited to synthetic v0.4 fixtures.
- v0.5 IAM, v0.4.5 public cloud Skill, v0.6 multi-Service access, or CASE008 enterprise four-layer runtime.
- Any production deployment or generalized claim before the external pilot gate.
