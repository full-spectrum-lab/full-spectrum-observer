## Scope decision

The v0.4 closure remains limited to the Scenario Pack knowledge-conflict pilot. The temporary
entry point is a local, single-item command-line Runner. It does not add v0.4.5 Cloud Skill,
remote access, RBAC/IAM, multi-service orchestration, automatic enterprise action, or changes to
Observer v0.5/v0.6 requirements.

## Implemented closure items

1. `observer scenario-pack-run` loads a signed Pack, validates the declared Golden Case, creates an
   idempotent batch, claims one item, executes the real Engine v1.5 facade, persists the candidate
   result/snapshot/evidence/observations, completes the batch, and emits a JSON result. The output
   explicitly retains `candidate_only=true`, `human_review_required=true`, and
   `authorized_action=false`.
2. Draft analysis tasks now enforce the backend Active-only preflight before Engine invocation.
   A Draft subject or bound knowledge version that is not `Active` is rejected with
   `PREFLIGHT_FAILED`; tasks that have already passed preflight are not re-gated during replay or
   recovery.
3. Batch item claiming now checks that both the item UPDATE and the batch UPDATE affect exactly one
   row. A stale or raced claim fails closed with `SCENARIO_PACK_BATCH_STATE_CONFLICT`.
4. `Observer.Host.Web` and `Observer.Store` restore the repository warning/analyzer discipline;
   related CA1305, CA1001, CA1869 and CA1310 issues were corrected.
5. The CI workflow includes a dedicated v0.4 Scenario Pack job, the aggregate `test-v04.ps1` gate,
   the pinned Engine/SQLite setup, and the complete .NET test suite.
6. The local authorized external-input path now accepts only a signed Pack with an
   `OWNER_LOCAL_PILOT:*` trust purpose, lowercase governance SHA-256 references, and a
   structured `assertion_key`/`polarity`/`evidence_role` input. It emits an Observer-owned
   candidate ledger row without altering the Engine-owned `ConflictObservation` contract.
   Arbitrary natural-language semantic inference is explicitly out of scope.
