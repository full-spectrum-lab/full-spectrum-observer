# Observer v0.4 社区持续证据任务

[English](COMMUNITY_EVIDENCE_TASK.md) · [简体中文](COMMUNITY_EVIDENCE_TASK.zh-CN.md) · [参与者操作手册](PARTICIPANT_RUNBOOK.zh-CN.md)

**研发关系：** `NON_BLOCKING_FOR_R&D`

**发布关系：** 本任务不授权 Release、部署或生产就绪声明

## 一、任务目的

这是一个面向未来 Observer v0.4 窄场景试点的社区持续证据任务。它希望在严格授权和数据边界下，逐步回答：

1. 独立人工能否检查脱敏质量并保留必要语义；
2. 真实目标用户能否在没有开发者逐步指导的情况下操作冻结候选；
3. 用户能否理解候选输出、证据引用、人工复核要求和 `UNKNOWN`；
4. 系统失败、分歧和少数证据能否被如实保留；
5. 删除与退出流程能否被执行和验证。

本任务不要求参与者证明 Observer 正确。`ACCEPT`、`CONDITIONAL`、`REJECT`、失败和 `UNKNOWN` 都是有效证据。

## 二、当前公开边界

- GitHub 当前公开版本真相仍以仓库根目录 README 为准；
- 本任务目前不提供可公开下载的 Observer v0.4 安装包；
- 执行阶段必须等 Owner 另行批准精确候选、SHA-256、任务范围和发放方式；
- RP-001 私有原文、Owner 私钥和未公开治理材料不属于社区资产，不得索取或传播；
- 本任务不阻断后续研发，但也不把 v0.4 外部验收状态改成 PASS；
- 本任务不会改变 v0.4、v0.4.5、v0.5 或 v0.6 的既有需求。

## 三、参与方式

### 方式 A：独立双角色参与者

一名参与者可以同时担任：

- 独立人工脱敏检查人；
- 真实目标用户。

前提是该参与者不是候选实现者、没有替数据所有者作出授权决定、被允许在本地检查原始材料与脱敏副本，并公开披露角色重合。

### 方式 B：只做目标用户

如果参与者无权查看原始材料，只能使用已批准的脱敏样本完成目标用户测试，不能签署独立脱敏结论。

### 方式 C：使用自己的材料

参与者可以使用自己合法拥有的材料。但如果同一人同时是数据所有者、脱敏检查人和目标用户，结果标记为：

```text
COMMUNITY_SELF_PILOT / NOT_INDEPENDENT_REDACTION
```

它可以帮助发现使用问题，但不能单独表述为独立外部验收。

## 四、未来执行需要形成的证据

1. 授权样本清单引用；
2. 不包含敏感原文的人工脱敏报告；
3. 目标用户试点验收记录；
4. 删除与退出记录；
5. 候选、Pack、输入和允许回传日志的 SHA-256；
6. 角色重合与利益冲突披露；
7. 失败、偏差、分歧和 `UNKNOWN` 清单。

严禁提交原始材料、可逆脱敏内容、私钥、密码、token、cookie、个人绝对路径或未经批准的截图。

## 五、现在如何表达参与意愿

在执行阶段开放前，可以在本仓库创建 GitHub Issue，标题为：

```text
[Community Evidence Interest] Observer v0.4 - <参与者简称>
```

Issue 只需说明：

- 国家/地区及时区；
- 是否独立于项目实现团队；
- 是否愿意提供自己合法控制的样本；
- 愿意承担脱敏检查、目标用户测试或两个角色；
- 可使用的操作系统；
- 不上传任何原始样本或不必要的个人信息。

创建 Issue 不代表已经获得内部候选或私有数据访问权。候选发放与正式执行仍需 Owner 单独授权。
