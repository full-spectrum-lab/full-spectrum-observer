# Runtime Provisioning (FSO v0.3 — Runtime Provisioning Closure, Option B)

This document describes the offline, staged, deterministic provisioning of the
self-contained Python runtime shipped at `runtime/python` inside the Observer
release package.

## Guiding constraints

- **Fully offline.** No network calls. `pip` and the 7 dependency wheels are
  hash-pinned in `engine/locks/python-runtime.lock.json` andresolved from a local
  wheel cache (`py312-verify-cache/wheels`).
- **Only the target interpreter.** Install uses `runtime/python/python.exe`
  exclusively — never system Python, conda, a `PATH` Python, or a managed/hosted
  Python.
- **No new lock fields are fabricated.** `provision-runtime-python.ps1` never
  writes the lock. `runtime_tree_manifest_sha256` is regenerated by
  `build-runtime-manifest.ps1`, not by `provision`.
- **No `FSP_PRIVATE_PYTHON` is set by provision.** The publish gate owns that
  env var; provision only builds the tree.

## Scripts

| Script | Purpose |
|---|---|
| `provision-runtime-python.ps1` | Copy embeddable tree → seed pip (explicit .NET ZIP API) → offline install deps → determinism cleanup → atomic swap into `runtime/python`. |
| `build-runtime-manifest.ps1` | Enumerate `runtime/python`, emit `engine/locks/runtime-manifest.json` with a reproducible `runtime_tree_sha256`. |
| `verify-runtime-manifest.ps1` | Re-enumerate, recompute, and compare against the manifest + lock. |

## provision-runtime-python.ps1 parameters

- `-PythonSource` (mandatory): a directory containing the extracted CPython
  3.12.8 embeddable (must contain `python.exe` whose SHA matches the lock).
- `-PythonArchive` (optional): the `python-3.12.8-embed-amd64.zip`. If supplied,
  its filename and SHA are validated against the lock. It is **never** guessed
  from an adjacent path.
- `-WheelCache` (mandatory): directory holding `pip-24.3.1-py3-none-any.whl` plus
  the 7 dependency wheels.
- `-Destination` (mandatory): release package root; the tree lands at
  `<Destination>/runtime/python`.
- `-LockFile` (optional, defaults to `../engine/locks/python-runtime.lock.json`).

## Validation order (fail-fast, before any copy/install)

1. `lock.version == 3.12.8` and `python.exe` SHA matches `python_executable_sha256`.
2. If `-PythonArchive` given: filename + SHA match `distribution.archive(_sha256)`.
3. `pip` wheel name / size / SHA match `pip.*`.
4. Each of the 7 `dependencies[*]` name / version / wheel / SHA match.
5. The wheel cache contains **no wheel not declared** in the lock.

Any mismatch throws immediately — nothing is copied or installed.

## Determinism

- `PYTHONDONTWRITEBYTECODE=1` is set for the whole script (including spawned
  `python -m pip`).
- After install, `__pycache__/`, `*.pyc`, and all `direct_url.json` are deleted.
- `python312.zip` is treated as an opaque blob (hashed whole, never expanded).
- `RECORD` / `INSTALLER` / `REQUESTED` / `METADATA` / `WHEEL` are kept and covered
  by the manifest; the manifest must account for **every** regular file in the
  tree (no "exclude the unknown" masking).

## Atomicity

The build runs in `runtime/_staging_python_<pid>`. The live `runtime/python` is
replaced only after all checks pass. On failure the staging dir is removed and
any existing valid runtime is left untouched.

## runtime_tree_manifest_sha256 lifecycle

- The original lock carried a non-reproducible (dangling) `runtime_tree_manifest_sha256`.
- `provision` + `build-runtime-manifest.ps1` make it reproducible.
- **First B4 build** produces a *candidate* `runtime_tree_sha256`. Per the gated
  process, this candidate is reported to the Owner and the lock is updated **only
  after Owner review**; a second build then re-verifies reproducibility. Until
  then `verify-runtime-manifest.ps1` will (correctly) report a lock/tree mismatch
  — use `-IgnoreLockMismatch` for that pre-update first run.
